## Practice Presets

- Store names and unit arrays in config.xml. Existing configs with no presets
  continue using their existing single-unit or multi-unit selection.
- A preset only changes the practice scope, not the study or question mode.
- Empty unit arrays explicitly represent all units. A named missing unit stays
  selected as unavailable; never silently expand it to the whole library.
- Work on a deep copy inside settings. Closing without Save and Close discards
  preset edits and scope changes together.
- New names must be nonempty, at most 60 characters and unique ignoring case.
- Applying a preset loads checkboxes. Editing checkboxes switches to a custom
  selection without modifying the saved preset.
- Updating or renaming an existing preset preserves its place in the list.
- Deleting a preset leaves the current checked units unchanged.
- All persistence uses the existing atomic config save path and backups.

## Verification

Use build.bat -RunTests for model, XML round trips, cancellation, apply/rename/
delete and sampling scope tests. Render the settings form at normal and compact
heights. Desktop input tests remain opt-in through -IncludeDesktopTests.

Do not add dependencies, change XML word/review schemas, migrate user data, or
publish v0.5 until the remaining modules and compatibility tests are complete.

## Remaining Acceptance Criteria (2026-10-23)

- Import preview captures a candidate library, preserves source text, reports
  missing fields and duplicate/ambiguous rows, and defaults to skipping existing
  vocabulary. Explicit updates may change reading and meaning only. Cancel and
  failed saves leave the live library unchanged. Confirmation rejects a stale
  preview if the library changed after preparation.
- Assign a stable local WordId distinct from SourceId. Preserve it across edits,
  imports, XML round trips and restart. Importing vocabulary never imports another
  user's progress or review events.
- Keep four independent scheduling states. Old aggregate scheduling is copied as
  the same baseline to all four directions, without inventing review events.
  New ratings change only the selected direction; total counts remain aggregates.
- Append a dated event with word ID, direction and rating on successful rating.
  Undo restores scheduling and marks the event undone; failed rating/undo saves
  roll back all in-memory changes. Browse and previous-word navigation do not log.
- Show per-word direction state and event history in the library UI.
- Preserve the pre-upgrade XML via the existing atomic-save backups. New records
  use schema version 1; unsupported future schemas are rejected. Downgrading to
  v0.4 requires restoring its pre-upgrade backup, not overwriting the new data.

The user explicitly approved completing these remaining v0.5 modules before
starting v0.6. The earlier no-schema-change boundary applied to the presets-only
slice; the additive word/review schema above is now in scope.
